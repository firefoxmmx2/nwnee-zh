# 常见问题

## 游戏黑屏 / 主菜单一片黑，只有光标

最常见的原因是**没有开 `NWNZH_TOUTF8=1`**。默认那一条 ToUTF8 补丁只挂在 NUI 的单个调用点上；
主菜单阶段还有别的路径会按 cp1252 重编码字符串，字符串被弄坏后界面就画不出来。
启动选项里显式写上：

```
env NWNZH_TOUTF8=1 LD_PRELOAD=$HOME/.local/lib/nwn-zh/libnwzh.so %command%
```

如果已经是这样仍然黑屏，先看日志里**每一处** `[nwzh] patch ... ok` 是不是都在。
出现 `skipped: unexpected bytes` 说明游戏版本不对（见下一条）。

另外：纯软件渲染（llvmpipe、没有 `/dev/dri`）下，启动画面能出来但主菜单阶段可能整屏黑——
这属于渲染后端问题，与本补丁无关。

## 界面里中文全是 `?`（早期版本的问题，现已修复）

早期版本会在两个地方写出 ASCII `?`，现在都堵住了：

1. **`?` 的个数与汉字一一对应** —— 源头在 `Encoding::FromUTF8`（`0x5fd8a6` 的
   `mov BYTE PTR [rdx+rax*1],0x3f`），cp1252 映射不了的字符就写成 `?`。
   现在 `FromUTF8` 遇到合法 UTF-8 直接透传；确认 `NWNZH_FROMUTF8` 没被设成 `0`。
2. **属性值里的符号变成 `?`/方块** —— 同一个 `FromUTF8` 路径，外加矮字形格子顶部混进了上一行
   字形的像素。后者由**搬墨**处理（见 [design.md](design.md)），`NWNZH_RELOCATE=0` 会让它回来。

如果现在还有 `?`，只剩一种情况：那些码点不在槽位表里（见 [patches.md](patches.md) 的槽位表），
或者字体本身没有该字形。后者需要换字体。

## 字体要用哪一种？

必须是**静态 TTF（`glyf` 轮廓）**，且**自带 CJK 字形**。汉化包里的
`NotoSansSC-Regular-static.ttf` 就是这种。**TTC 和 CFF（`.otf`）都不行** —— 引擎用 stb_truetype，
只认 `glyf` 表。

同一个文件复制改名成四份放进 `override/`，内容完全相同也没问题，运行时按档位分别烘焙
14 / 16 / 17 三个字号：

```
override/fnt_default.ttf        ← 14 号正文
override/fnt_default_hr.ttf     ← 16 号（高分辨率档）
override/fnt_maintext.ttf       ← 17 号主文本
override/fnt_galahad14.ttf      ← 位图优先，靠 remap 才落到 TTF
override/jbmonoreg.ttf          ← NUI 等宽字体
```

少任何一份都会让对应控件缺字。

只改字形范围而不换字体是没用的：stb 会跳过字体里找不到的码点，图集尺寸不变，
界面上仍然是空的。反过来，字体换了但补丁没打，图集只有 `512x128`。

## 日志里出现 `skipped: unexpected bytes`

游戏更新了，二进制布局变了。本补丁的地址是针对 **8193.37-17**（Steam build `20277208`）的。
其它版本会安全跳过（每个补丁点改之前都 `memcmp` 原字节），不会写坏二进制，但也就不会生效。
上游版本适配需要重新反汇编定位。

## 提示 `Could not divine nwn base data directory`

启动时的工作目录不对。必须 `cd` 到游戏的 `bin/linux-x86` 目录再启动 `./nwmain-linux`，
或者用 Steam 启动（Steam 会自己设置工作目录）。

## 图集太大 / 显存不够 / 花屏

默认图集是 4096²（RGBA 64MB）。占满 70% 且字号大于 18 时会自动升到 8192²（256MB），
日志里会有 `atlas escalate 4096->8192`。显卡纹理上限较低时可以用环境变量压回来：

```
NWNZH_ATLAS=2048
```

同理 `NWNZH_ATLAS=8192` 可手工强制放大。值必须是 2 的幂，范围 1024–16384。

## 某个符号显示成方块

先分清两种情况：

- **格子顶部有一条黑边或小黑点**（角色名里 `D/d/m/v` 头顶那种）——不是缺字形，是引擎的行框
  装进了上一行字形的像素，由搬墨处理；`NWNZH_RELOCATE=0` 会让它重现。
- **整体是个空心方块**——该码点不在槽位表里，解码后落到空格，在等宽字体里就是一个方块。
  `▪`、`♀`、`—` 这类符号原本就是这样，现已覆盖 U+2010–2015 / U+2190–21FF /
  U+25A0–25FF / U+2600–26FF。仍在范围外的符号需要扩槽位表（改 `src/nwzh.c` 的 `NWZH_I_*`
  和 `NWZH_N_TOTAL`，C1/C2 的上界会自动跟着变）。

## 新建角色时崩溃

历史问题，原因是解码桩少存了一个 caller-saved 寄存器（`%rsi`），导致 markup 分支拿到错指针。
当前版本已修（`STUB_D2` 默认开启）。如果自己改过桩的 push 序列，注意栈对齐：
入口 `rsp%16 == 8`，`call` 时要凑成 0。

## 会影响存档 / 联机吗？

不会。补丁只在进程内存里改指令字节，不写磁盘、不改游戏文件、不改存档，
也不改变发给服务器的数据。不设 `LD_PRELOAD` 就完全恢复原状。

## 支持 Windows / macOS / 其它平台吗？

不支持。整套东西依赖 x86-64 ELF 的具体指令字节与 PIE 加载方式，是 Linux 专用的。

## 为什么不直接改游戏文件？

改二进制文件既不可逆又容易在 Steam 校验时出问题。运行期内存补丁的好处是：
一个 `.so` 就是全部改动，删掉 `LD_PRELOAD` 立刻回到原版，失败时也只是补丁跳过。
